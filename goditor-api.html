MCP 도구 71개 · 로컬 HTTP(127.0.0.1) · Claude 데스크톱 / Claude Code

GODITOR는 MCP 서버를 앱 안에 내장하고 있습니다. Claude가 이 서버에 붙으면 캔버스를 직접 읽고, 섹션을 만들고, 블록을 고칩니다. 사람이 화면을 보고 있는 바로 그 프로젝트를 조작합니다 — 따로 파일을 주고받지 않습니다.

먼저: GODITOR 앱이 켜져 있어야 합니다.

MCP 서버는 별도 프로그램이 아니라 앱에 내장되어 있습니다. 앱을 켜면 127.0.0.1:9345 에서 함께 뜨고, 앱을 끄면 같이 사라집니다. 앱이 꺼져 있으면 Claude 쪽에서는 「도구가 없다」 또는 「연결 실패」로만 보입니다.
바깥에서는 접속할 수 없습니다. 이 서버는 내 컴퓨터(127.0.0.1) 안에서만 열립니다. 인터넷으로 열려 있지 않고, 원격에서 붙일 방법도 제공하지 않습니다.

1. 연결하기

앱의 환경설정 → 개발자 탭을 열면 「연결 명령」이 그대로 준비되어 있습니다. 아래는 그 명령이 무엇인지에 대한 설명입니다.

Claude Code (터미널)

환경설정 → 개발자 탭에서 연결 명령을 복사해 터미널에 붙여넣습니다. 모양은 이렇습니다: 

claude mcp add goditor -- node "<브리지 스크립트 경로>"

<브리지 스크립트 경로> 는 앱이 자기 사용자 폴더에 복사해 둔 claude-pm/mcp-stdio-bridge.cjs 입니다. 경로는 설치 위치·계정마다 다르므로 개발자 탭에 표시된 값을 그대로 쓰세요(직접 조합하지 마세요).

Claude 데스크톱

claude_desktop_config.json 의 mcpServers 에 다음을 넣습니다: 

{
  "mcpServers": {
    "goditor": {
      "command": "node",
      "args": ["<브리지 스크립트 경로>"]
    }
  }
}

토큰은 여기 적지 않습니다. 브리지가 실행될 때마다 앱에서 최신 토큰을 직접 읽어갑니다 — 그래서 앱을 재시작해 토큰이 바뀌어도 설정을 다시 고칠 필요가 없습니다.

앱을 두 개 띄웠다면

포트가 겹치면 9345 부터 하나씩 올라갑니다(9345~9365). 브리지는 기본적으로 살아 있는 인스턴스 중 가장 낮은 포트에 붙습니다. 특정 인스턴스에 못박으려면 환경변수 GODITOR_MCP_PORT 로 포트를 지정하세요.

2. 접속 토큰

도구 호출은 전부 토큰을 요구합니다. 토큰이 없거나 틀리면 401 입니다. 내 컴퓨터 안에서만 열리는 서버지만, 같은 컴퓨터의 다른 프로그램이 마음대로 캔버스를 고치게 둘 수는 없기 때문입니다.

  • 발급 — 앱을 켤 때 자동으로 새로 만들어집니다. 사람이 신청하거나 결제할 것은 없습니다.
  • 확인 — 앱의 환경설정 → 개발자 탭 「접속 토큰」에서 보거나 복사합니다.
  • 보관 — 현재 토큰은 사용자 폴더의 claude-pm/mcp-<포트>.json (권한 0600, 소유자만 읽기)에 기록됩니다. 개발자 탭에 그 경로가 표시됩니다.
  • 재발급 — 같은 탭의 「재발급」 버튼. 눌러도 브리지로 연결한 Claude는 다음 호출부터 새 토큰을 자동으로 읽습니다. 토큰을 설정 파일에 직접 적어둔 경우에만 그 값을 갈아 끼워야 합니다.

직접 HTTP로 호출한다면 헤더에 실으세요 — x-goditor-token: <토큰> 또는 Authorization: Bearer <토큰>. 엔드포인트는 POST /mcp (JSON-RPC 2.0), 상태 확인은 GET /health 입니다. /health 는 토큰 없이 열려 있지만 토큰 값은 절대 실어 주지 않습니다 — 어느 인스턴스인지와 토큰 파일의 «경로»만 알려줍니다.

토큰은 내 캔버스를 고칠 수 있는 열쇠입니다. 화면 공유·스크린샷·이슈 붙여넣기에 섞여 나가지 않게 하세요. 새어 나갔다면 「재발급」 한 번이면 됩니다.

3. USER_BUSY — 사람이 우선입니다

사용자가 캔버스에서 무언가를 입력하고 있는 동안에는, 화면을 바꾸는 도구가 거부됩니다. 응답은 이렇게 옵니다: 

{
  "ok": false,
  "code": "USER_BUSY",
  "message": "사용자가 편집 중입니다.",
  "retryAfter": 2000
}

자동화가 사람이 치는 글자 위에 덮어쓰면, 사용자 입장에서는 앱이 글자를 먹은 것으로 보입니다. 그래서 「기다리게」 만들어 두었습니다. 지키는 쪽이 따를 규약은 짧습니다:

  • 1회만 잠시 뒤 재시도합니다(retryAfter 만큼). 무한 재시도 금지.
  • 그래도 막히면 사람에게 말합니다 — 「지금 편집 중이신 것 같아요, 끝나면 다시 적용할게요」.
  • 우회하지 않습니다. 프로젝트 파일(proj_*.json)을 직접 고치는 건 금지입니다 — 열려 있는 앱이 그 위에 다시 저장해 버리므로 바뀐 내용이 조용히 사라집니다.

읽기 도구에는 이 가드가 없습니다. get_canvas_state, read_section, get_section_memo 같은 조회는 사용자가 편집 중이어도 언제나 돌아옵니다. 그 외에 자주 만나는 코드는 NOT_FOUND(blockId가 사라졌거나 잘못됨 — get_canvas_state 로 다시 읽으세요) 입니다.

5. 짧은 예시

연결이 끝났으면, Claude에게 평소 말로 시키면 됩니다. 도구 이름을 외울 필요는 없습니다: 

「지금 열려 있는 캔버스 읽어서, 두 번째 섹션 제목을
 '무릎이 편한 하루'로 바꿔줘」

→ get_canvas_state 로 blockId 를 찾고
→ update_block 으로 그 블록만 고칩니다
→ 사용자가 마침 그 블록을 입력 중이면 USER_BUSY 로 물러났다가 다시 시도합니다

update_block 한 번은 되돌리기(Cmd+Z) 한 단계와 같습니다. 한 의미 단위는 한 호출로 담는 편이 사용자에게 편합니다.

6. 알아둘 것

  • 도구 목록과 스키마는 앱 버전을 따라갑니다. 이 페이지는 훑어보기용이고, 정확한 값은 언제나 접속한 앱의 tools/list 응답입니다.
  • 블록 삭제·이동·순서 변경은 도구로 되는 것과 안 되는 것이 갈립니다. 안 되는 요청에는 「현재는 안 됩니다」라고 답하는 편이 낫습니다 — 우회하다 캔버스가 깨집니다.
  • 이미지는 data: URL 로 밀어넣을 수 있지만 길이 제한이 있습니다 (대개 20만 자). 큰 이미지는 앱의 자산·스크래치패드를 거치세요.
