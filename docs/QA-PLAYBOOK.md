## 1. 유저 렌즈 — 「누구의 눈으로 보는가」

★**상태가 아니라 사람으로 나눈다.** 정본은 `ops/qa/lenses.json`.

| 렌즈 | 누구 | 이 사람만 겪는 것 |
|---|---|---|
| 처음 온 사람 | 비로그인 | 여기가 «뭐 하는 곳인지» 알 수 있나 |
| 가입만 한 사람 | 앱 0개 | 빈 상태가 «덜 만든 것»으로 보이나 |
| 앱 하나 쓰는 사람 | 가장 흔함 | 카드 한 장의 정렬 |
| 앱 여럿 | 카드 2장+ | 간격·정렬이 무너지나 |
| 주문한 사람 | 주문 1건+ | 표·경고문이 뜨나 |
| 기한 임박 | 15일 남음 | «곧 끝난다»가 보이나 |
| 운영자 | tier 99 | 구매로 못 가는 등급이 티가 나나 |
| 세션 끊긴 사람 | 낡은 토큰 | 오류가 «사람 말»인가 |
| **JS 안 도는 사람** | 스크립트 차단 | ★`opacity:0` 로 시작하는 요소가 **영영 안 보이면 백지** |
| 느린 네트워크 | 3G 급 | 첫 화면이 «비어 보이나» |

⚠️**아직 렌즈에 없는 것**(다음에 넣을 것): 두 탭 동시 · 뒤로가기 · 딥링크 직접 접근 ·
폼 더블클릭 제출 · 아주 긴 이름/이모지 입력 · 화면 낭독기(스크린리더).

## 2. 렌즈별 검사

러너가 자동으로 본다: **안 보이는 요소 · 화면 밖 · 가려진 글 · 죽은 링크 · 낮은 대비 ·
가로 스크롤 · 본문 없음 · 콘솔 오류.**

손으로 봐야 하는 것:
- 처음 온 사람 → 히어로만 보고 «무엇을 파는 곳»인지 말할 수 있나
- 가입만 한 사람 → 빈 카드에 «다음에 뭘 하면 되는지»가 있나
- 세션 끊긴 사람 → 「다시 로그인해 주세요」 + 갈 곳

> **§4-15 는 오늘 제일 오래 헤맨 것이다.** 같은 「대비 미달」 증상에 원인이 **셋**이었다
> (테마 미확인 · gradient-text · 템플릿 이스케이프). 앞의 둘을 고쳐도 증상이 그대로여서
> 「진짜 결함인가」로 기울 뻔했다.
> ★**증상이 안 바뀌면 「덜 고친 것」이 아니라 «원인이 하나 더 있는 것»일 수 있다.**
> ★그리고 판별법은 하나였다 — **같은 계산을 «다른 경로»로 한 번 더 해 보는 것**
> (수동 CDP 로는 17.59:1 이 나왔다. 그 차이가 곧 답이었다).

**공통 규칙 넷**
1. **파이프를 걷고 원시 출력을 한 번 봐라.** 특히 «막 고친» 도구의 «첫 숫자».
2. **판정 축과 결론 축이 같은지 봐라.** 「이 축에서 0건」은 「결함 0」이 아니다.
3. **오류를 삼키는 catch 를 만들지 마라.** 삼키면 그 위 모든 판정이 거짓말이 된다.
4. ★**「전부 실패」는 검사기가 틀렸다는 뜻이다.** 72조합이 «전부» 걸리면 대상이 아니라
   도구를 의심해라. 실제로 2026-09-03 첫 실행이 그랬다(전 렌즈 72건 = 전 조합).

### ★★그리고 이것 하나 — 오늘 제일 뼈아팠던 것
**「함정을 문서에 적는 것」과 「도구가 그 함정을 피하는 것」은 다른 일이다.**
§4-11(테마 키·적용 확인)을 이 문서에 적어 놓고 러너에는 반영하지 않아서,
첫 실행이 통째로 오탐이 났다.
⇒ **§4 에 항목을 더할 때는 «probe.mjs / run.mjs 어디에 반영했는지»를 같이 적어라.**
  반영 안 한 항목은 «아직 못 막는 함정»으로 따로 표시한다.

## 6. 파일을 「갈랐을」 때 (CSS/JS 분리)

⛔**선택자 자동 측정을 믿지 마라.** 가상클래스를 벗기다 선택자가 망가진다
(`.kko` 를 「3장이 쓴다」고 했는데 실제로는 1장이었다).

**판정은 두 가지로만:**
1. **마크업·JS grep** — 그 클래스가 실제로 어디 있나
2. ★**분리 전후 「계산 스타일 대조」** — 영향받는 **모든 페이지**를 재서 **차이 0건**

★2026-09-03 에 `home.css` 분리가 이 대조에서 걸렸다(`opacity 1→0`). **8장만 보고 배포했다가
되돌렸다** — 다음엔 **18장 전부 대조한 뒤** 배포한다.

**선언 보존 검사**도 같이: 분리 전 CSS 선언 집합 ⊆ 분리 후 합집합. 잃은 선언 0건.

## 7. 배포 후 «반드시»

```
1. CSS/JS 를 고쳤으면 ?v= 를 «같이» 올린다   ← 안 올리면 옛 파일이 나간다(실제로 두 번 당함)
   ★현재 버전을 파일에서 «읽어» 올린다. 고정 문자열 치환 금지(패턴이 안 맞으면 조용히 넘어간다)
2. git push  →  EC2 수동 배포  →  Cloudflare purge
3. 라이브에서 «실제로» 확인한다 (curl 로 그 문자열이 나오는지)
4. api/ 파일은 docroot 가 아니라 «원래 경로»로 — 그리고 systemctl restart
```
⛔`/tmp` 통째 cp 금지 · `git add -A` 금지 · docroot 안에 백업 금지

## 7-b. 서버 쪽 «감시»가 뭐가 있나 (2026-09-03 기준)

| 타이머 | 주기 | 무엇을 |
|---|---|---|
| `mail-queue-watch.timer` | 5분 | 메일이 5분 넘게 큐에 갇혀 있나(발송기가 맥이라 맥이 꺼지면 멈춘다) |
| `api-health-watch.timer` | 5분 | API 가 응답하나. **2회 연속** 실패에만 알린다 |
| `db-backup.timer` | 매일 03시 KST | DB 를 EJSON+gzip 으로 뜬다. 7일 보관 |

★셋 다 «상태 변화»만 알린다(장애 시작·복구). 5분마다 울리지 않는다.
★셋 다 «일부러 깨뜨려» 알림이 실제로 오는 것까지 확인했다. **안 해봤으면 「감시가 있다」고 말하지 마라.**

**감시를 새로 만들 때 지킬 것**
1. ⛔맥이 아니라 **EC2 에서** 돌려라 — 맥이 꺼진 걸 감시해야 하는데 감시자도 같이 죽으면 소용없다.
2. **「몇 회 연속」을 세라.** 한 번의 순간 실패로 울리면 곧 아무도 안 본다.
3. **정상 응답이 무엇인지 확인해라.** `/api/license/session` 은 POST 전용이라 **GET 은 405 가 정상**이다.
   200 을 기대하면 «영원히 장애»로 보인다.
4. ⛔**오류를 삼키지 마라.** 감시가 조용히 죽으면 「감시가 있다고 믿는」 상태가 제일 위험하다.
